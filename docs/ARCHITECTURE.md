# Архитектура EGO

Документ описывает, из чего состоит EGO и как части связаны. Состояние на 2026-11-06, первая некоммерческая версия (ядро 0.1.7.dev1, клиент 0.9.3).

## Три части

| Часть | Где в проекте | Что делает |
| --- | --- | --- |
| **Core** (ядро) | `server/ego_core/` | Фоновый процесс: API, база, модель, память, аккаунты, сеть. Единственный источник истины. |
| **Control Center** | `windows_ui/` | Окно Windows для управления: модель, пресеты, журналы, настройки, доступ с ноутбука и туннель. Работает поверх Core. |
| **Клиент** | `EGO-Client/` (в репозитории пока не загружен) | Веб-интерфейс, который Core отдаёт по адресу `/app/`. Открывается в браузере. |

Модель не является отдельной частью: её запускает Core через `llama-server` (llama.cpp с CUDA) и обращается к нему по локальному HTTP.

## Схема

```
Браузер (клиент /app/)  ──HTTP 127.0.0.1──┐
Телефон / ноутбук       ──HTTPS (домашняя сеть или туннель)──┤
                                           ▼
                                    Core (API)
                                    ├── service.py   — истории, сообщения, генерация, стрим
                                    ├── memory.py    — факты и конспект по каждой истории
                                    ├── presets.py   — пресеты настроек модели
                                    ├── accounts.py  — вход по почте и коду, сессии
                                    ├── store.py     — зашифрованная база (SQLCipher)
                                    ├── content_guard.py — проверка запретов
                                    ├── lan.py / tunnel.py — доступ с других устройств
                                    └── vault/       — ключи, шифрование, TLS
                                           │
                                           ▼
                                    llama-server (модель GGUF на видеокарте)
```

Control Center общается с Core через управляющий API и не хранит данные сам.

## Хранение данных

- `data\` — зашифрованная база `main.db` (истории, персонажи, миры, память, аккаунт, журнал входов). Ключи защищены Windows (DPAPI) и открываются только под тем пользователем Windows, который их создал.
- `settings\` — профили моделей, `mail.json` (пароль почты в зашифрованном виде), `network.json`.
- `logs\` — журналы без текста историй. Ротация при каждом старте: не больше 30 файлов каждого вида.
- Браузер — копия историй для офлайн-работы клиента. На ПК она не нужна, на ноутбуке и телефоне удаляется при выходе.

Эти папки никогда не попадают в репозиторий (см. `.gitignore`).

## Основные модули Core

| Файл | Назначение |
| --- | --- |
| `api.py` | HTTP API, проверка доступа, заголовки безопасности |
| `service.py` | Генерация ответов, стрим, остановка, перегенерация, «Продолжить» |
| `sage_prompt.py` | Сборка системного промпта: персонаж, мир, память, правила роли |
| `memory.py` | Извлечение фактов каждые N сообщений, сжатие в конспект, бюджет токенов |
| `enchant.py` | Помощник «Enchant your prompt»: улучшение текста полей |
| `content_guard.py` | Шаблонные проверки запретов на вводе, ответе и памяти |
| `presets.py` | Четыре пресета: Баланс, Длинные сцены, Короткие ответы, Экономия VRAM |
| `preflight.py` | Проверка конфигурации при старте: модель, порты, VRAM, место на диске |
| `accounts.py`, `mailer.py` | Аккаунт, коды входа, сессии, отправка писем |
| `lan.py`, `tunnel.py` | Доступ с ноутбука по HTTPS и туннель Cloudflare |
| `errors.py` | Каталог кодов ошибок с текстом и подсказкой |
| `store.py`, `keys.py`, `vault/` | База, ключи, шифрование, сертификаты |
| `logrotate.py` | Ротация журналов |
| `control.py`, `daemon.py` | Команды `core start/stop/status/check/open-client` |

## Слои безопасности

1. **Сеть.** API на 127.0.0.1 без TLS. Для других устройств — отдельный HTTPS-слушатель только на частных адресах ПК, с самоподписанным сертификатом. Туннель по умолчанию выключен.
2. **Вход.** Почта, пароль от 10 символов и 6-значный код из письма. Блокировки: 5 неверных кодов — 15 минут, 10 неверных паролей — 1 час, общий лимит 30 попыток в минуту.
3. **Права.** Аккаунт с другого устройства даёт только клиентские права. Управление Core, выдача кодов запуска и остановка доступны только с самого ПК.
4. **Данные.** Шифрование базы, хранение ключей через Windows, журналы без текста историй.
5. **Контент.** Шаблонный фильтр на вводе, ответе модели и памяти. Это страховка, а не гарантия; запрет на реальных людей задан в правилах модели и кодом не проверяется.

## Известные ограничения

Полный список: `docs/KNOWN_LIMITATIONS.md` (в проекте, в репозиторий попадёт при загрузке кода). Коротко по архитектуре:
- Одна генерация одновременно: второй запрос получает `CORE_BUSY`.
- Удаление истории в Core удаляет всё, но в браузере копия удаляется только при синхронизации.
- Очередь задач для медиа-генерации пока не реализована.
