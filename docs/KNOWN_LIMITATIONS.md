# Известные ограничения

## Первая версия (этап 5, 2026-11-05)

Проверено: 586 автотестов (0 failed), проверка `scripts/smoke_release.py` на Модель D (8B) Q8_0 / RTX 3060 (12 из 12),
запуск на реальной установке пользователя. Ниже — то, что работает не идеально или ещё не проверено.

**Нужно действие пользователя**
- Вход с настоящего ноутбука не проверялся: проверены HTTPS по адресу ПК и правила доступа с ПК.
  Нужны ноутбук в той же сети, письмо с кодом и разрешение Python в брандмауэре Windows (частная сеть).
- `EGO.exe` и `EGO-Core.exe` пересобраны 2026-11-05 из текущих исходников. После каждого изменения кода их нужно
  пересобирать (`packaging\build_exe.py --install`, Core остановлен); `START_EGO_CLIENT.bat` сначала использует `.venv`,
  поэтому при работе через BAT всегда идёт текущий код. Окно `EGO.exe` после пересборки вручную не открывалось.

**Модель (Модель D (8B))**
- Память чата: модель иногда пропускает важный факт или записывает лишний («Торн не называет Миру по имени»).
  Поэтому в окне «Память чата» факты можно править, удалять и закреплять.
- Сжатие старых фактов в конспект проверено тестами, но на реальной модели в долгой истории (сотни сообщений) ещё не проверялось.
- Модель иногда пишет действия за пользователя и изредка вставляет английские слова.
- Пресеты замерены только на RTX 3060 12 GB.

**Возможности, которых пока нет**
- Удаления истории в Core нет: удаление в клиенте убирает её только из браузера, а история и её память остаются в базе.
- Аккаунты создаёт владелец в окне сервера (вкладка «Доступ»); все аккаунты видят одни и те же истории и персонажей установки. Аватара профиля пока нет.
- Суперадмин (временная функция для диагностики) не реализован.
- Перегенерировать и продолжить можно только последний ответ; правка старых сообщений меняет только копию в браузере.

**Безопасность и приватность** (этап приватности, 2026-11-05)
- Сделано: клиент больше не загружает шрифты Google (раньше каждый запуск сообщал Google IP-адрес) и не делает
  сторонних запросов вообще (проверяется тестом); ответы API не кэшируются браузером (`no-store`); строгая политика
  CSP без встроенных скриптов, запрет встраивания страницы, `no-referrer`. На ноутбуке при выходе, отзыве сессии
  с ПК или её истечении копия историй, персонажей и миров в браузере удаляется (на самом ПК — никогда).
  Журналы проверены: текста историй, паролей, кодов и токенов в них нет. В реестре остались только пути к модели и llama-server.
- Сертификат для домашней сети самоподписанный: браузер ноутбука предупреждает один раз. При смене адреса ПК
  выпускается новый сертификат с новым отпечатком.
- На ПК клиент работает по HTTP на 127.0.0.1 (за пределы компьютера не выходит). Копия историй на ПК лежит
  в `localStorage` браузера без отдельного шифрования — так же защищена, как профиль браузера Windows-пользователя.
- Истории, созданные на ноутбуке, не видны в клиенте на ПК и наоборот: список историй клиента хранится в браузере,
  а сами истории — в Core.
- Запреты на несовершеннолетних, реальных людей и содержание без согласия проверяются в коде шаблонами текста (ввод, ответ модели,
  память): это страховка, а не гарантия. Запрет на реальных узнаваемых людей задан только в правилах модели и кодом не проверяется.

## M1.7

- Полный набор тестов на Windows (2026-11-04): 0 failed; пропуски — symlink без прав Developer Mode и
  POSIX-only проверки.
- Рассказчик (история без персонажа) в основном пишет во втором лице, но 8B-модель иногда всё же решает за героя.
- Персонажи и миры хранятся в Core (D2), включая карточки GUI-песочницы. Без запущенного Core песочница карточки
  не показывает. Групповые сцены и сцены с заметкой отправляют профиль текстом.
- Синхронизация клиента разрешает конфликт в пользу Core: если запись менялась и офлайн, и на сервере,
  офлайн-правка заменяется (клиент сообщает об этом).
- `EGO.exe`: разработческие действия Control Center (наборы pytest, fixture/environment/diagnostics, холодный
  бенчмарк) недоступны — они требуют исходников и `.venv`. Клиент как отдельный exe не собирается: он открывается
  через `/app/` из Core (`START_EGO_CLIENT.bat` или `EGO-Core.exe open-client`).
- Загрузку модели (~5.5 с: llama.cpp + CUDA) ускорение запуска не затрагивает.
- Пресеты замерены только на RTX 3060 12 GB с Модель D (8B) Q8_0. На другой карте или модели перепроверьте
  `runtime/benchmarks/presets.py`.
- Модель 8B иногда вставляет отдельные английские слова в русский текст.
- Клиент: редактирование старых сообщений меняет только локальную копию, история в Core не меняется.
  Перегенерировать и продолжить можно только последний ответ. Групповые сцены идут через одного «Рассказчика».
- Сессия клиента живёт до перезапуска Core; после него откройте клиент снова через `START_EGO_CLIENT.bat`.
- Приватность сознательно отложена на финальный этап: карточки персонажей GUI лежат в реестре
  (`HKCU\Software\EGO`), данные клиента — в `localStorage` браузера, API клиента без TLS на loopback.

## M1.3

- Нативные Windows 11 BAT/cmd, пути с кириллицей, DPI, named pipes, DPAPI/DACL, Job Object и Windows TCP teardown ожидают проверки. Linux/offscreen Qt их не подтверждает.
- Реальных llama-server b11724, Модель D (8B) Q8_0 и RTX 3060 в тестовой среде не было. Fixture HTTP-процесс проверяет transport/lifecycle, не загрузку GGUF, VRAM или 39–41 tokens/s. GPU Verification остаётся NOT_VERIFIED.
- Soft cancel закрывает локальный transport; длительная GPU-операция может не прерваться мгновенно. Если backend не восстанавливается после bounded timeout, используйте явный Runtime restart. Бесконечной автоматической перезагрузки нет.
- Одна генерация одновременно; конкурентная новая операция получает CORE_BUSY. Модель занимает VRAM до stop/restart/Core shutdown; idle eviction и освобождение памяти под игры не входят в M1.3.
- GUI benchmark при работающем Core — тёплая генерация. Холодный MODEL/restart-peaks BAT06 запускайте с остановленным Core. Fixture не является GPU inference.
- Production key unlock требует исходного Windows-пользователя DPAPI. Переносимый application backup/recovery, key rotation и workflow certificate renewal не реализованы. TLS identity действует 365 дней и fail closed при истечении. Не храните единственную копию важных данных в development-хранилище.
- API loopback-only. Shutdown/runtime restart/configure требуют installation header; встроенные клиенты обновлены. Bearer-only data/status сохранены. LAN/mobile/device auth/SwiftUI/full REST+WS sync — M2.
- История ограничена последними 100 entries. Schema v1; future/foreign/incomplete schemas отклоняются без reset. Retention cleanup отсутствует.
- Linux sandbox запрещает AF_UNIX: реальная IPC-интеграция пропущена с причиной, как и native DPAPI test. Критические SQLCipher проверки выполнены, SQLite не подставляется.
- Диагностика — allowlist metadata, без raw stdout/приватных traceback/prompts/ответов. Некоторые детали OMITTED_FOR_PRIVACY; первичный RuntimeFailure сохраняет cause и числовые коды.
- Character engines, long-term memory, worlds/groups, scheduler, stable installer/update manager — последующие этапы. M1.3 не объявляет весь EGO v1.0 завершённым.

## Добавлено 2026-11-06

- **Enchant на модели 8B.** Модель не соблюдает просьбы о длине, поэтому длину держит лимит токенов. Иногда она пишет с грамматическими огрехами, а в приветствии может описать реакцию других персонажей. Результат всегда можно откатить.
- **Туннель** зависит от бесплатного сервиса Cloudflare quick tunnel. Адрес меняется при каждом включении, гарантий доступности Cloudflare не даёт. Если связь обрывается, туннель закрывается с кодом TUNNEL_STOPPED, включите его снова. **Приватность:** трафик туннеля идёт через серверы Cloudflare, и они расшифровывают его (HTTPS заканчивается у них), то есть технически могут видеть переписку. Туннель выключен по умолчанию, включается только владельцем на ПК; для приватного доступа используйте домашнюю сеть по HTTPS (docs/LAN_ACCESS.md).
- **PIN устройства** работает только при открытии по `https://` (домашняя сеть или туннель). По обычному `http://` браузер не даёт хранить его безопасно, клиент об этом предупреждает. PIN защищает от постороннего с разблокированным телефоном, но не от того, кто открыл инструменты разработчика браузера. Для этого есть режим «Не хранить истории на этом устройстве».
- **Права на папку EGO** EGO не меняет; настройки безопасности Windows тоже.
- **Мобильная раскладка** включается при ширине экрана до 760 px. Проверена на снимках 375×812 (Edge, режим телефона) и на iPhone пользователя; на Android отдельно не проверялась.
- **Петли повторов.** Небольшая модель может зациклиться и повторять один ответ. С 06.11.2026 повторившийся ответ не передаётся модели, факты памяти, которые его цитируют, тоже, и включён лёгкий DRY. На реальной петле это сняло повтор в 6 случаях из 6. Сохранённая история не меняется.
- **Вопросы вне роли** (`((…))`, `[OOC: …]`): модели 8–12B отвечают на них ненадёжно и часто остаются в роли. Подсказка для OOC есть, но гарантии нет.
- **Модель и язык.** Модель D (8B) переходит на английский (в тесте английские слова были в 29 ответах из 95). Модель A (12B) в том же тесте не дала ни одного английского слова.
- **Память на длинной истории.** На 6 вопросов о деталях из начала 42-ходовой истории модели без памяти EGO ответили верно в 1–3 случаях. Память EGO помогает, но мелкие детали (напиток, происхождение шрама) могут теряться.
- **Карточки-примеры** (Мара, Лира, Вега, Торн) без возраста и характера. Модель играет их сдержанно и может отказать незнакомцу в близости. Чтобы персонаж был открыт к роману, это нужно прописать в карточке.
